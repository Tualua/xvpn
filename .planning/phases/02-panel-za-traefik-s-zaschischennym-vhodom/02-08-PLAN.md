This plan's slice: **every push re-proves the admin gate on the production templates and the pinned Traefik image in minutes, so a router regression cannot reach main unnoticed; and no push can commit a real secret value.**

`scripts/check_secrets.py` (stdlib only, like check_no_log.py; DOC-04 second clause; the planner's choice of mechanism for the checker's fix route: a check.sh step instead of narrowing DOC-04): file set = `git ls-files -z` of the root argument when it is a git work tree, otherwise every regular file under it (self-test temp dirs); skip binary files (NUL byte in the first 8 KiB). Three rules, each finding printed as `<path>:<line>: <rule> (<key or pattern name>)` with the value never printed:
1. `secret-literal` (all paths except `.planning/`, whose prose is covered by rules 2 and 3): a YAML `key: value`, env `KEY=value` or INI `key = value` line whose key matches, case-insensitive, `password|passwd|secret|token|api_?key|private_key|gate_path|cookie_value`, and whose value (surrounding single or double quotes removed, a trailing ` #` comment removed) is secret-shaped: 16 or more non-whitespace characters of any kind (base64 `/`, `+`, `=` and special characters such as `!@#$%&*~^` included) that contain either at least one letter and one digit, or characters from at least three of the classes lowercase, uppercase, digit, other. Not secret-shaped and therefore allowed: empty values, values containing `{{` or `lookup(` or `!vault` or `$ANSIBLE_VAULT`, `<...>` placeholders, the CHANGE_ME family, simple filesystem paths under a path-named key (the key, case-insensitive, ends in `_file`, `_dir` or `_path` and does not end in `gate_path`, AND the whole value matches `^/[A-Za-z0-9._/-]+$`), URLs (value contains `://`), identifiers with fewer than three classes and no digit (for example `panel-secrets.yml`). The path exemption is decided by key name first, never by value shape alone: under any other secret key (`..._secret`, `password`, `token`, `gate_path`, `cookie_value`, ...) a value starting with `/` is scanned like any other value, so a random base64 secret that happens to start with `/` and carry no `+` or `=` is still flagged.
2. `jwt-shape` (all paths): three base64url segments starting with the JWT header prefix, joined by dots, each at least 10 characters.
3. `pem-private-key` (all paths): a PEM private-key armour line.
Allow-list: a `secret-literal` finding is suppressed only when the line ends with the marker comment `# xvpn-test-fixture: non-secret` AND the path starts with `scripts/gate/` or `extensions/molecule/`; rules 2 and 3 have no allow-list.
